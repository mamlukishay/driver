    דף האירוע הוא לוח הושבה. שתי לשוניות, הלוך וחזור. למעלה "ממתינים להסעה", צ'יפים של ילדים שצריכים את הנסיעה. מתחת רכבים עם מושבים: מלא מציג אווטאר, פנוי מצויר כמושב מקווקו. נוגעים בילד/ה ואז במושב.

    נהג/ת

    הסדרן

    מאמץ בנייה M–L

    ההורים רק עונים על שאלות, והאפליקציה מציעה את ההושבה. כשיש מספיק תשובות היא בונה "הצעת שיבוץ": מקבצת ילדים לפי קרבה לבית, ממלאת מקומות, מכבדת מי רוצה איזה כיוון ושומרת על הוגנות. המארח/ת או כל נהג/ת לוחצים "אשר ושלח".

    הרשמה לאירוע
    ערימת כרטיסים: "נועה מגיעה?" ← "צריכה הלוך? חזור?" ← "את/ה יכול/ה להסיע? כמה מקומות". 20 שניות.
    נהג/ת
    אומר/ת רק "אני יכול/ה להחזיר, 4 מקומות" ומקבל/ת ילדים ומסלול איסוף מסודר עם זמנים משוערים.
    מד חוסרים
    "חסר נהג אחד להלוך" + "בקש מהקבוצה": שיתוף ב-WhatsApp עם קישור שנפתח ישר בשאלה "אני יכול/ה להסיע".
    הוגנות
    מונה לכל משפחה, "הסעת 3 פעמים החודש". האפליקציה מעדיפה מי שהסיע פחות.
    התראות
    Web Push (PWA מותקן; ב-iOS 16.4+ רק אחרי הוספה למסך הבית) + Scheduled Function: ערב לפני, 30 דק׳ לפני. "יצאתי" שולח Push לכל הורה של נוסע. WhatsApp כגיבוי.
    אירועים חוזרים
    תבניות שבועיות (חוג כל יום ג׳) עם רוטציה. מתאים כי הסדרן כבר מאזן תורות.
    חלקים טכניים
    פונקציות + Blobs + Scheduled Function + מפתחות VAPID + web-push + מנויי Push לכל משפחה. geocoding של כתובות פעם אחת בהרשמה (Nominatim).

    בקשות והצעות

    מאמץ בנייה M

    דף האירוע הוא פיד שנראה כמו הצ'אט, רק מסודר. שני סוגי כרטיסים: בקשה ("נועה צריכה הלוך") והצעה ("יש לי 3 מקומות בחזור, יציאה 13:30"). לכל כרטיס פעולה גדולה אחת, וכרטיס שנסגר מתקפל ל"סגור ✓". מד החוסרים לשני הכיוונים דבוק למעלה.

    הרשמה לאירוע
    נוגעים בילד/ה ← "צריך/ה הלוך / חזור / שניהם / מסתדרים" ← נוצר כרטיס בקשה.
    נהג/ת
    "אני יכול/ה להסיע" ← כיוון + מקומות ← כרטיס הצעה. או "אני לוקח/ת" על בקשה של מישהו.
    יומן append-only
    כל פעולה היא blob משלה (event/{id}/log/{timestamp}-{rand}), והמצב = הרצה מחדש של היומן. אין התנגשויות כתיבה, יש היסטוריה מלאה, וביטול = פעולה מפצה.
    התראות
    WhatsApp בלחיצה, ואופציה אוטומטית: בוט Telegram או נושא ntfy לכל משפחה, למי שרוצה. במצב נהג "הגעתי לנועה" שולח להורה "אני למטה 🚗" בלחיצה אחת.
    אירועים חוזרים
    "חזור על הבקשה כל שבוע" על כרטיס בקשה. בהמשך.

    זהות, כתובות, התראות ונתונים

    SPA סטטי ב-Vite + Preact, ניתוב History API עם כתובות אמיתיות (/* /index.html 200 ב-_redirects), Netlify Functions + Netlify Blobs, polling כל ~15 שניות כשדף אירוע פתוח. בלי מסד נתונים חיצוני ובלי חשבון נוסף.

    זהות בלי סיסמה: מעקות, לא מנעולים

    • ההרשמה יוצרת משפחה ומפתח משפחה אקראי ב-localStorage. השרת שומר רק hash, וכל כתיבה נבדקת מולו.
    • שבב "פועל/ת בתור: משפחת כהן" קבוע בכותרת, וצבע המשפחה מופיע בכל מקום שהיא מופיעה.
    • כל כתיבה היא משפט אישור ("להושיב את נועה ברכב של משפחת לוי, הלוך, 10:00?"), טוסט ביטול ל-10 שניות והיסטוריה של האירוע.
    • מכשיר שני: "שלחו לי את הקישור שלי" פותח WhatsApp אליכם עם /me/devices#…. המפתח ב-fragment, כך שלא מגיע ללוגים.
    • קישור ילד/ה: כתובת עם token לקריאה בלבד, בטוחה לטלפון של ילד.
    • תמונת רכב (רשות): עוזרת לילדים לזהות את הרכב ביציאה. נדחסת בטלפון ל-~800px ונשמרת ב-Blobs תחת car/{familyId}/{carId}. בלי תמונה: אייקון רכב בצבע המשפחה.

    מי רואה איזה מספר

    • חברי הקבוצה רואים שמות בלבד.
    • מספר מופיע רק למי שחולקים רכב באותו כיוון: הנהג/ת רואה את המספרים של הנוסעים ושל ההורים שלהם, והורי הנוסעים רואים את המספר של הנהג/ת.

    סולם ההתראות

    מתחילים מהשלב שעולה אפס ועובד לכולם, ומטפסים רק כשיש סיבה.

    1. גרסה 1WhatsApp בלחיצההאפליקציה מנסחת טקסט ופותחת wa.me/<phone>?text= להורה, או wa.me/?text= לבחירת הקבוצה. ההורה לוחץ שליחה. חינם, בלי API. אי אפשר לכוון מראש לקבוצה.
    2. אופציהTelegram bot / ntfyPush אמיתי ואוטומטי, חינם, בלי התקנת PWA. צריך /start לבוט פעם אחת, או נושא ntfy לא ניתן לניחוש (הוא הסיסמה). זו עוד אפליקציה להורים.
    3. גרסה 2Web Push + Scheduled Functionתזכורת ערב לפני ו-30 דק׳ לפני, "יצאתי" אוטומטי. VAPID + web-push מפונקציה. ב-iOS 16.4+ רק אחרי הוספה למסך הבית ואישור מלחיצה.
    4. לא בשבילנוWhatsApp Cloud APIדורש חשבון Meta Business, מספר ייעודי ותבניות מאושרות, מחיר לכל הודעה (ומ-אוקטובר 2026 על יותר קטגוריות), ושליחה לקבוצות מוגבלת לעסקים זכאים. CallMeBot שולח רק לעצמך; ספריות לא רשמיות מפרות את התנאים ודורשות שרת שתמיד דולק.

    יצירת אירוע מתמונת ההזמנה

    ב-/g/:group/new הדבר הראשון הוא אזור גרירה ו"בחר/י הזמנה מהגלריה". אחריו טופס מלא מראש שבו השדות שזוהו מסומנים ("זיהינו מההזמנה — בדקו"): כותרת, תאריך, שעת התחלה, שעת חזור, מקום וכתובת. הכל ניתן לעריכה, וכלום לא נשמר עד "צור אירוע". אם בהזמנה כמה זמנים (טקס 10:30, ארוחה 12:30), ההתחלה היא הראשון והחזור המוצע הוא האחרון ועוד משך טיפוסי, עם רמז לבדיקה.

    מומלץClaude vision דרך Netlify Functionתמונה ← JSON {title, date, times[], place, address}. Haiku 4.5 בשביל העלות או Sonnet 5.5 בשביל הדיוק. הכי טוב עם פונטים מעוצבים בעברית. שבריר סנט להזמנה; מפתח API במשתני הסביבה של Netlify.
    חינםTesseract.js בדפדפןמודל heb + regex לתאריכים ושעות. בלי שרת, אבל חלש מול פונטים מעוצבים, והורדה של ~10–20MB בשימוש הראשון.
    תמיד זמיןידניהתמונה נשמרת כעטיפה בלי זיהוי. זה הגיבוי כשהזיהוי נכשל.
    • אחסון: הדפדפן מקטין ודוחס (canvas ← WebP/JPEG בערך 1600px, בערך 200–300KB), פונקציה שומרת ב-Blobs תחת invite/{groupId}/{eventId} ומגישה עם cache headers. עדיין בלי מסד נתונים.
    • פרטיות: ההזמנה גלויה רק לקבוצה (קוד קבוצה לא ניתן לניחוש בכתובת) ולא נסרקת במנועי חיפוש.
    • שיתוף: ההזמנה כתמונת התצוגה בשיתוף ב-WhatsApp (Open Graph דרך edge function) בגרסה 1.1.

    עברית לתצוגה, אנגלית לקוד

    המלצה ומפת דרכים

    מתחילים בלוח, מוסיפים אוטומציה כשהיא מרוויחה את מקומה

    לבנות את A כגרסה 1, ולקחת שני דברים מ-C: יומן הפעולות append-only (בלי התנגשויות, עם היסטוריה וביטול) ופעולת "אני לוקח/ת" בלחיצה על ילדים שממתינים.

    התראות בגרסה 1: WhatsApp בלחיצה ומצב נהג. בגרסה 2: תזכורות מתוזמנות ו-Web Push מ-B למשפחות שמתקינות את ה-PWA, ואז אירועים חוזרים עם רוטציה.

    1. v1MVP

      הרשמת משפחה, קישור הזמנה לקבוצה, יצירת אירוע (מתמונת ההזמנה, ידני כגיבוי), RSVP וצורך לכל כיוון, הצעת רכב, הושבה, מד חוסרים, סיכום ו"יצאתי" ב-WhatsApp, קישור ילד/ה, היסטוריה וביטול.

    2. v1.1יום ההסעה

      מצב נהג עם מסלול ב-Maps/Waze, ‎.ics, שכפול אירוע, ההזמנה כתמונת תצוגה בשיתוף (Open Graph).

    3. v2אוטומציה

      Push מ-PWA ותזכורות מתוזמנות, אירועים חוזרים עם רוטציה, מונה הוגנות.

    4. v3אולי

      שיבוץ מוצע (הסדרן של B) ככפתור אופציונלי "הצע שיבוץ".
